# 审核人员说明与测试步骤

## 测试前提

本扩展直接使用第三方 AI 网页。审核人员无需向开发者提供任何凭据，可使用未登录状态测试基础加载，也可使用审核人员自己的测试账号验证登录态。

## 首次运行

1. 安装扩展后会打开“数据与隐私设置”页面。
2. ChatGPT Cookie 选项默认关闭。
3. 点击“保存选择并打开扩展”进入网格页。
4. 顶栏“隐私”入口可随时返回并修改选择。

## 核心功能测试

1. 在“站点”中只启用一个或两个可访问的站点，减少第三方服务限流影响。
2. 在对应站点的“原始页面”中完成登录或验证码（如需要）。
3. 在顶栏输入框输入测试问题并点击“同时提问”。
4. 验证问题被填入并发送，回答随后显示在卡片正文区。
5. 点击“复制”，验证剪贴板包含 Markdown 和富文本格式。

## Cookie 权限行为

- 关闭选项：扩展不会调用 Cookie API 建立 ChatGPT Cookie 请求规则，ChatGPT iframe 可能以匿名状态运行。
- 开启选项：Chrome 会先显示可选 `cookies` 权限提示；用户同意后，扩展读取 `chatgpt.com` 中 SameSite 不是 `no_restriction` 且 path 为 `/` 的 Cookie，只在扩展网格 tabId 对应、requestDomains 为 `chatgpt.com` 的会话规则中追加 Cookie 请求头。
- 再次关闭选项：扩展撤销可选 `cookies` 权限并重建网格页会话规则。
- 关闭网格标签页后，对应会话规则被删除。

## 响应头修改范围

扩展会对自己的网格 tabId 下 `sub_frame` 请求移除阻止 iframe 的 CSP/X-Frame-Options 响应头。规则不会匹配其他标签页。该行为用于在单一界面并排显示用户选择的 AI 网页，不用于绕过 AI 模型安全策略、付费限制、账号限制或内容审核。

## 外部服务波动

第三方 AI 站点可能临时改版、限流或要求验证码；这类状态会在卡片顶部显示。审核失败若仅发生在某一第三方站点，可使用其他启用站点验证扩展核心流程。
