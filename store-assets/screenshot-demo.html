三者处在同一条异步执行链上

事件循环负责安排任务执行，Promise 把异步结果表达成状态，async/await 则让 Promise 链写得更接近同步流程。

  • 同步代码先执行
  • Promise 回调进入微任务队列
  • 当前任务结束后清空微任务

从运行顺序理解

JavaScript 先跑调用栈中的同步代码，再由事件循环挑选可执行任务。Promise 的 then 和 await 后续部分通常作为微任务运行。

await value 可以近似理解为把后续逻辑放进 Promise.resolve(value).then(...)。

最小示例

console.log('A')
Promise.resolve().then(() => console.log('B'))
console.log('C')

输出是 A、C、B，因为 Promise 回调是微任务，会在当前同步代码结束后执行。

async/await 不会阻塞线程

await 只暂停当前 async 函数的后续执行，主线程仍可继续处理其他代码。当等待的 Promise 完成，后续部分被安排为微任务。

所以它改善的是代码表达，不是创建新的线程。

可以这样记

  • 事件循环：调度机制
  • Promise：异步结果模型
  • async/await：Promise 的语法层

三者不是互相替代，而是从底层调度到上层写法的不同抽象层次。
